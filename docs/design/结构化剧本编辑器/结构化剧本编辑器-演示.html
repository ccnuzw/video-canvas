结构化剧本编辑器
原型稿

把剧本从一段 Markdown 变成「场次 + 元素」

现在每集剧本是一整段 Markdown，对白、人物名、括号全靠手打符号，改几下就乱。这次把剧本拆成场次和元素（动作、角色、括号、对白、转场……）分行存进数据库，人物和地点有自己的表和 ID。 拆解、分镜、上集衔接这些下游本期一行不改：每次写结构时顺手渲染一份和今天格式一样的 script_md 给它们读。

阅读说明。现状来自 2026-11-21 对仓库代码的核对；新设计都是提案，尚未实现。准绳是同目录的 结构化剧本编辑器.md，这里的每个决定都能在那里找到。界面长什么样看右上角「原型稿」。

一次写入怎么走

不管是用户在编辑器里改、模型生成、Agent 修改还是粘贴，最后都落到同一个事务里。

写入来源编辑器直接给结构；模型 / Agent / 粘贴给的是文本
解析（只对文本）Go 里唯一一个解析器，认不出的行当「动作」保存
与旧结构合并同一场保留短标题、梗概、情绪；没改的行沿用原 ID；备注跟着相邻行走
校验对白必须有说话人、闪回成对；不合法整集不写（67043）
一个事务落库增改删场次 / 元素 → 渲染 script_md → revision+1
下游照旧拆解、分镜、上集衔接、字数估价仍读 script_md
设计：结构是唯一真源，script_md 降为派生列。这样选了行级表（用户定），又不用一次改 7 处下游；解析器只在 Go 里写一份，前端粘贴也调后端，避免两套规则越改越不一样。
兜底：
  • 格式认不出（比如自定义提示词让模型写成了散文）：每行都当「动作」存下，不失败，编辑器顶部提示「有 N 行未识别」。
  • 已锁定集：结构只读；script_md 冻结在锁定那一刻，人物改名也不重渲染，分镜里的 @资产名 不会失配。
  • 老剧本：第一次打开剧本页时整部剧一次转换，锁定集只补建结构、原文不动。

三种写入方式

差别在于有没有解析和合并这一步。

编辑器直接写结构
PUT …/script最常用

不经过解析。前端提交整集场次和元素，带 ID 的是已有、不带的是新增、没出现的就是删除；服务端比对后增改删。

文本写入
解析 + 合并

重新生成剧本、Agent 的 drama_update_episode、多行粘贴。文本先解析，再和旧结构合并，手动加的场次信息和备注尽量保留。

存量转换
整部剧一次自动

项目上 script_structured=false 时触发。全部集一个事务转换。未锁定集换成渲染结果，锁定集只建结构。

剧本写好后点「资产拆解」，会发生什么（第⑤步）

剧本解析成结构后，人物、地点、道具和出现集数都已经有了，拆解不再让模型读一遍剧本重新提取，否则两边会对不上。

  1. 按人物表建角色卡所选集里出现过的人，已有节点就复用并补集数，没有就新建，回填 canvas_node_id。
  2. 按地点表建场景、按每场 props 建道具道具按名字去重，和画布上已有的道具合并。
  3. 出现集数从结构统计哪集有这人的角色行、哪集有这个地点的场次，直接算出来。
  4. 一次轻量模型调用补充造型、外貌、音色只能引用已有人物和地点的 ID，冒出新名字的条目丢弃并记警告；一个人多个造型就建多个角色节点，都认回同一个人。
  5. 锁定所选集，接着写资产提示词和现在一样。
边界：
  • 模型补充失败时，资产仍以默认造型、空描述建好，任务标警告，可重跑补充，不卡住拆解。
  • 拆出来的身份只来自两张表：剧本里没出现的人不会凭空多出一张角色卡。
  • 它是第⑤步，编辑器上线后单独发版；在那之前拆解照旧，拆完按名字回填 canvas_node_id。
用户选的方案 1。放弃了「完全不调模型」（会丢掉按剧本识别戏服变化的能力）和「剧本角色行可选造型」（写剧本时多一道选择，编辑器和表都要再加一层）。

把「林川」改名「林骁」时，会发生什么

名字是身份，不是正文，所以已锁定的集也允许改名，但它们的文本不动。

  1. 在人物表里改名重名返回 67045；「林川」自动进别名，以后模型再写「林川」也能认回同一个人。
  2. 所有角色行即时显示「林骁」元素存的是人物 ID，不存名字，所以不用改元素。
  3. 未锁定集重渲染 script_md这些集 revision+1 并逐集推送更新；发起改名的页面自己重读当前集，不弹冲突。
  4. 锁定集 script_md 不变它们已经拆过资产、可能已出分镜，文本和画布资产名得保持一致。
边界：画布资产不跟着改名。
  • 人物表和画布角色节点靠 canvas_node_id 关联，资产名要在资产管理里自己改。
  • 锁定集的剧本文本仍写「林川」，编辑器里显示「林骁」，两者在锁定集上会不一致。
  • 前提：这部剧必须已整部转换，否则没转换的集里旧名是纯文本，改不到。改名前会先触发转换。

上线说明里要写清：改名不改画布资产名，也不改已锁定集的剧本文本。

第一次打开一部老剧时，会发生什么

不做一次性回填：迁移里不能跑 Go 逻辑，单独的回填命令又要运维执行。

  1. 打开剧本页，读结构发现项目 script_structured=false。
  2. 一个事务里转换全部集逐集解析 script_md，说话人和地点按名字、别名登记进两张表（标「待确认」）。
  3. 未锁定集：script_md 换成渲染结果，revision 不变只是格式归一，不算内容变化；升了的话，用户手里的旧 revision 会让随后改标题、钩子白白 409。
  4. 锁定集：只建结构script_md 原样保留，revision 不变。
  5. 置 script_structured=true以后不再转换。
验收口径（可自动断言）：转换前文本和渲染结果各自解析成「(场次标题, 元素类型, 说话人, 文本)」序列，两边逐项相等；空白、全半角标点差异不算。用开发库里现有短剧剧本全部跑一遍。

整集被重新写入时，保留什么、丢什么

选一个场景：左边是数据库里的旧结构（含用户手写的场次短标题、梗概、情绪和紫色备注），中间是模型或 Agent 新写的文本（可以直接改），右边实时显示合并结果。 这里的解析和合并在浏览器里模拟，规则与设计文档 §7.1、§7.4 一致；真实实现在 Go 后端。

// 所有写入最终都走这里（提案）
func writeEpisodeScript(tx, drama, ep, next Structure, baseRevision) error {
  ensureStructured(tx, drama)                 // 整部剧未转换就先转换
  if ep.Locked            { return ErrDramaEpisodeLocked }   // 67005
  if ep.Revision != baseRevision { return ErrCanvasConflict } // 409
  if err := validate(next); err != nil { return ErrScriptInvalid(err.Scene, err.Index) } // 67043
  diffAndApply(tx, ep, next)                  // 按 ID 增、改、删场次和元素，重排 position
  ep.ScriptMD = render(next, roster, locations)   // note 不渲染
  ep.Revision++
  return tx.SaveEpisode(ep)
}

// 文本写入：重新生成、Agent、粘贴覆盖整集
func writeEpisodeText(tx, drama, ep, text) (Stats, error) {
  parsed, warnings, newPeople := parse(text, roster, locations)  // 认不出的行 → action + warning
  registerUnconfirmed(tx, newPeople)          // confirmed=false
  merged, stats := merge(loadStructure(ep), parsed)
  return stats, writeEpisodeScript(tx, drama, ep, merged, ep.Revision)
}

// 合并（§7.4）
func merge(old, neu) {
  for s in neu.scenes:                        // 键 = 内外 + 时间 + 地点ID，不要求顺序
    o = first unused old scene with key(s)
    if o: s.id, s.title, s.summary, s.emotions = o...; s.elements = mergeElements(o.nonNote, s.elements)
  mergeElements: LCS on (type, character_id, text) → 保留原 ID
                 未匹配区间里 type+character_id 相同的按顺序配对 → 修改，保留原 ID
  notes: 挂到原前一个元素后；它没了就往前找同场仍保留的元素；整场删了 → 第一场开头 + 警告
         插入点后紧跟括号 / 对白时往后挪到这段说话结束（不能夹在角色行和对白之间）
  extra_character_ids、props 以新文本为准
}
