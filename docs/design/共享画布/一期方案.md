# 共享画布：一期方案

评审稿。目标是让普通画布拥有与短剧一致的三种共享方式。三种方式同一期交付；“先做只读”只是开发顺序，不是上线范围。

## 三种方式，两个去处

所有者从画布顶部或「个人画布」卡片菜单打开同一个「共享画布」弹窗，输入其他已注册且启用的账号邮箱。默认选「共享只读」。不需要对方先成为查看成员，也不需要交换文件。

| 方式 | 接收方在哪里看到、能做什么 | 原画布、已有成员和后续更新 |
| --- | --- | --- |
| 共享只读 `view` | 「共享给我 → 画布」出现原画布，可平移、缩放、读节点内容、预览图像和播放音视频。 | 所有者继续编辑。接收方刷新或回到前台可见最新已保存版本，不承诺实时同步。所有者可撤销，成员可退出。 |
| 推送副本 `copy` | **由所有者发起**，接收方直接在「个人画布」得到有新 ID 的可编辑副本，可用自己的账号继续生成。 | 原画布及查看成员不变。双方以后互不影响；发送方不能通过撤销共享收回副本。副本不继承成员。 |
| 转移所有权 `transfer` | 接收方在「个人画布」得到独立可编辑画布，成为唯一所有者。 | 交付成功才让原画布退役。原所有者失去访问权，原查看成员和旧链接失效，不自动跳转到新画布。新所有者按需重新授权。 |

「共享给我」沿用作品页现有入口，内分「画布 / 短剧」，保留旧短剧筛选链接。弹窗成员列表仅列**可查看原画布的人**，不是副本接收记录。转移须二次确认，显示画布标题、目标邮箱及“转移后你和现有查看成员将无法打开原画布”。副本发送成功留在原画布；转移成功返回个人作品列表。

## 只读可见什么

仅适用于未删除的普通画布；短剧专属画布仍随短剧共享。共享读页展示作者已保存的布局、分组、连线、节点正文、提示词和已保存的媒体结果。授权前提示作者：**对方能看到节点内容和提示词，不只是成片**。不展示 Agent 对话、运行日志、账单或作者素材库。

只读页不出现「接管编辑」，不自动保存、不写草稿、不对账回填任务，不允许生成、上传、导出整图或再共享。服务端对列表封面、详情和每次媒体请求均校验当前授权；媒体只限该画布可见内容所引用、且来源归属已验证的素材，不下发作者原始文件地址。撤销阻断后续读取，不承诺收回已经看过或保存到本地的内容。

## 副本和转移交付什么

- **交付已保存版本。** 在编辑器发起时先保存本地改动，保存失败或有版本冲突则不提交。保留标题、节点位置、分组、连线、提示词、创作参数、已持久化结果及可用封面。节点主素材、历史版本、参数引用、角色补图和声音等均须按类型清点；同一素材在多个节点出现只复制一次，所有引用改写到接收方名下。
- **不交付账号历史。** 不迁移 Agent 会话、任务队列和任务编号、生成账单、本地草稿、共享成员或仅对作者有效的账号绑定。旧作品的历史费用留在原账号，接收方之后生成使用自己的额度。无法独立交付的必需资源必须报明原因并阻止交付，不能留下表面成功但打不开的节点。
- **不交付仍在变化的作品。** 只读授权不必等待任务。副本和转移若遇到正在生成、拆分镜或可能回写的 Agent 运行，提示“画布还有任务进行中，请结束后重试”。提交期间若源版本变更，要求刷新后重新确认，不默默换用别的版本。
- **不出现半次转移。** 必需素材缺失、复制失败、容量超限或提交冲突时，接收方看不到半成品，原画布和成员不变，已准备的临时对象可回收。只让这张源画布退役，不删除作者素材库中的原文件，以免影响作者的其他作品。

## 实现边界

沿用[短剧共享服务](../../../backend/internal/service/drama_share.go)的两条路径：`view` 写授权关系，`copy` 和 `transfer` 共用交付服务。沿用[画布导入导出](../../../backend/internal/service/canvas_transfer.go)的引用扫描、素材复制和 ID 改写能力，但不能直接串联现有导出、导入、删除三个接口：普通导出允许跳过缺失素材，转移还要求新建与原作退役同时成功。具体事务和鉴权边界见[技术要点](技术要点.md)。

## 一期验收

| 场景 | 可观察结果 |
| --- | --- |
| A 重复授权 B；B 同时知道 A 的另一张画布 ID | 列表仅一条；B 能读授权画布，不能读取另一张的封面、详情或素材，也不能用普通写接口、CLI 或 Agent 改原作。 |
| A 保存、撤权，或 B 主动退出 | 保存后刷新看到新版本；撤权或退出后的下一次请求无法再获取画布和媒体，重新授权才恢复。 |
| A 向 B 推送含图片、声音和多处素材引用的副本 | B 从个人列表打开、编辑、预览结果；A 更改或删除原作不影响 B。原查看成员看不到新画布。 |
| A 转移给 B，原先 C 可以查看 | 成功后只有 B 拥有新画布；A、C 均不能通过源 ID 或旧媒体地址重新读取；历史账单不变。 |
| 使用自己、未注册或停用账号的邮箱，或对短剧专属画布发起操作 | 不创建授权或交付记录，不改变作品归属；未注册和停用邮箱不分别暴露状态。 |
| 提交时任务仍活跃、素材缺失，或交付中版本变化、存储失败 | 返回可操作的失败原因；原作和成员保留，无半成品；失败原因消除后可重试。 |
| 双击提交、超时重试，或两个接收方并发接收同一原作的转移 | 同一次请求最多生成一个目标；两次竞争转移最多一次成功。即使响应丢失也能确认原请求结果。 |

实施顺序：先贯通授权、撤销和只读媒体，再完成独立副本，最后在同一交付事务上加入转移和二次确认。三种方式全部通过验收才算一期完成。不含匿名公开链接、查看者自行另存副本、多人共同编辑或跨账号实时推送。
