# 短剧开拍预设后台化

> 目标：把开拍设置里的「题材 / 画风」从编译期 JSON 搬到后台集中维护（新增、编辑、排序、启停、预览图），
> 运营不用发版就能加一条画风。
>
> 状态：设计待确认（2026-11-25）。基线 `local/0.7.3` @ `b82e6525`。

## 1. 现状（有取证）

| 事实 | 证据 |
|---|---|
| 题材 12 类 + 画风 12 种硬编码在随二进制编译的 JSON 里 | `backend/internal/drama/styles.json` |
| 包初始化时解析，之后只读，返回切片副本 | `backend/internal/drama/resources.go:10`（`//go:embed`）、`:33`（`builtinStyles`）、`:100`（`Styles()`） |
| 公开接口直接把这份内存目录吐出去 | `backend/internal/handler/drama.go:23` → `GET /api/v1/drama-styles`（`router.go:300`） |
| 建剧 / 改项目时用同一份目录校验 `style_key` | `backend/internal/service/drama.go:478`（`checkDramaStyle`） |
| 画风描述注入提示词（剧本、片场转写都走它） | `backend/internal/service/drama_scripts.go:134-140`、`drama_adapt_text.go:33` |
| 前端会话内缓存一次，不主动失效 | `web/src/hooks/use-drama-styles.ts` |
| 预览图是前端静态文件 + 前端硬编码白名单 | `web/public/drama-styles/*.webp`、`web/src/components/drama/pickers.tsx:21`（`STYLE_PREVIEW_KEYS`）、`:225` |
| 前端测试强制「清单里每个 key 都必须有对应 webp」 | `web/src/tests/components/drama/pickers.test.tsx:49` |

**结论**：加一条画风现在必须改代码 + 补静态图 + 发版。这是要解决的问题。

## 2. 目标 / 非目标

**做**

- 后台新增、编辑、排序、启停、删除题材与画风；画风可上传预览图。
- 公开接口按后台数据返回，且带预览图地址。
- 老数据（已建项目引用的 `style_key`）不受后台操作破坏。

**不做**

- 不做用户级 / 租户级自定义画风（用户侧仍只有开拍设置里那个「自定义画风」文本框）。
- 不动单集时长档位、画幅、模型选择——那些是能力约束，不是内容预设。
- 不做版本化与回滚（`settings/showcase` 也没做，同一档复杂度）。
- 不迁移现有 12 张 webp 到对象存储（理由见 §4.3）。

## 3. 数据模型

新表 `drama_presets`（迁移 `0049_drama_presets.sql`）：

```sql
CREATE TABLE drama_presets (
    id          BIGSERIAL PRIMARY KEY,
    kind        varchar(8)  NOT NULL,              -- genre | style
    key         varchar(32) NOT NULL,              -- 创建后不可改
    name        varchar(64) NOT NULL,
    prompt      text        NOT NULL DEFAULT '',   -- 仅 style 用
    preview_url varchar(1024) NOT NULL DEFAULT '', -- 仅 style 用
    sort_order  int         NOT NULL DEFAULT 0,
    enabled     boolean     NOT NULL DEFAULT true,
    is_builtin  boolean     NOT NULL DEFAULT false,
    created_at  timestamptz NOT NULL DEFAULT now(),
    updated_at  timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX uq_drama_presets_kind_key ON drama_presets (kind, key);
CREATE INDEX idx_drama_presets_kind_order ON drama_presets (kind, sort_order);
```

**为什么一张表而不是两张**：题材与画风共享 `key / name / sort_order / enabled` 四个字段和整套 CRUD 语义，
只有 `prompt / preview_url` 是画风专有。拆两张表会让后台 CRUD、排序、启停写两遍。用 `kind` 区分，
`prompt` 对题材恒为空串，校验里约束。

**seed**：迁移里 `INSERT` 现有 12 题材 + 12 画风，`is_builtin=true`，`sort_order` 按当前数组下标，
`preview_url` 填相对路径 `/drama-styles/<key>.webp`。seed 的 prompt 必须与 `styles.json` 逐字一致，
由后端测试断言（`TestSeedMatchesBuiltin`：读 embed 的 JSON，与迁移 seed 的数据比对），防止两边漂移。

**key 规则**：`^[a-z0-9_]{1,32}$`。不复用 `style_key` 的 `varchar(32)` 之外的约束——`drama_projects.style_key`
只有长度约束、没有外键，所以 key 改名会静默切断历史项目的画风关联。**key 一律只读**，后台新建时录入，
之后编辑弹窗里灰掉。

## 4. 生效链路

### 4.1 目录读取：注入式覆盖 + 进程内缓存

保持 `drama.Styles()` 的签名不变（handler / service 共 5 处调用点不用改），在 `internal/drama` 内加：

```go
// SetCatalogSource 由启动流程注入 DB 目录加载器；未注入或返回空时回落编译期内置。
func SetCatalogSource(load func(context.Context) (StylesView, error))
// InvalidateCatalog 后台写入后调用，下一次读取重新加载。
func InvalidateCatalog()
```

- 首次读取加载并缓存，`atomic.Pointer` 持有；
- **60 秒 TTL 兜底**：多副本部署时后台改完，其它副本最多 60 秒后跟上（当前部署是单 backend，TTL 只是保险）；
- DB 查询失败：用上次缓存；从未成功过则回落内置并记 `Error` 日志（**不能让开拍整体不可用**）；
- 表为空（迁移没跑 / 回滚）：回落内置，并在启动日志里 `Warn` 一次。

> 不把 DB 依赖塞进 `internal/drama` 是为了保住它的可测性（现在整个包零外部依赖、纯函数 + embed）。
> loader 函数由 `initialize/app.go` 注入，`internal/drama` 只认 `func(ctx) (StylesView, error)`。

### 4.2 校验语义（关键取舍）

`checkDramaStyle` 必须改成**只校验「存在」，不校验「启用」**。

原因：`service/drama.go:451` 在项目保存的**任何字段**变更时都会调用它（改标题、改集数都走这条路）。
若把停用当作不存在，运营停掉一条画风后，所有引用它的老项目会连标题都改不了——这是必然发生的事故。

所以：

| 场景 | 行为 |
|---|---|
| 新建剧 / 改画风 | 只能选 `enabled=true` 的（清单里根本没有停用项） |
| 老项目保存其它字段 | 放行（画风存在即可，哪怕已停用） |
| 老项目回显名称 | 查全量（含停用）拿 `name`；查不到（已删）则显示 key 本身 |

### 4.3 预览图

- 公开接口的 `styles[].preview_url` 直接给绝对或相对 URL，前端不再拼路径、不再查白名单。
- 存量 12 张：seed 写相对路径，继续由前端 nginx 提供 `/drama-styles/*.webp`。
  **不迁到对象存储**——迁了之后存量部署的画风选择器就依赖存储配置是否可用，而这个项目刚出过
  OSS 欠费停服（`UserDisable`）导致全站历史图裂图的事故；静态资源留在前端发布包里更稳，代价 500 KB。
- 后台新增：`POST /admin/drama-presets/:id/preview`（multipart，限 2 MB，只收 `image/webp|png|jpeg`）。

  **实现时改了方案（原方案存 `URL()` 的结果，是错的）**：
  - 本地存储的 `URL()` 给的是 `/files/<key>`，而 `/files` 是按 `assets` 表反查存储的，
    预设预览图没有素材行 ⇒ 存这个地址必然 404；
  - 对象存储在私有桶下 `URL()` 返回带 ttl 的预签名地址 ⇒ 存进表里过期即裂图。

  所以预览图有**自己的公开路由**：`GET /api/v1/drama-presets/previews/*`（不鉴权，key 里是 uuid，
  与 `/files` 同一套安全性）。迁移 0049 给表加 `preview_key` + `preview_storage_id` 两列，
  路由按 key 反查预设拿到所在存储：本地存储由后端直出（复用 `storage.FileServer`），
  对象存储现签名后 302。地址因此**永不过期**，换默认存储也不影响历史图。
  `preview_url` 存 `/api/v1/drama-presets/previews/<uuid>.webp`，与静态相对路径共用同一个字段，
  前端只认这个字段，不关心图在哪。
- 删条目时如果 `preview_key` 非空，顺手删对象；内置条目的静态图不归后端管，不动。

## 5. 接口契约

### 5.1 公开（改）

`GET /api/v1/drama-styles` → 只返回 `enabled=true`，`styles` 增加 `preview_url`：

```json
{
  "genres": [{ "key": "suspense", "name": "悬疑推理" }],
  "styles": [{ "key": "hyperreal_cg_3d", "name": "超写实3A级CG", "prompt": "…", "preview_url": "/drama-styles/hyperreal_cg_3d.webp" }]
}
```

老客户端不认 `preview_url` 会忽略，向后兼容。响应头加 `Cache-Control: public, max-age=60`
（照 `handler/showcase.go:13` 的做法），配合 §4.1 的 TTL，后台改完最多 1 分钟全网生效。

### 5.2 后台（新）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/admin/drama-presets?kind=style` | admin | 全量（含停用），按 `sort_order` |
| POST | `/admin/drama-presets` | admin | 新建，body `{kind,key,name,prompt?,preview_url?}` |
| PUT | `/admin/drama-presets/:id` | admin | 改 `name/prompt/preview_url/sort_order`（不接受 key/kind） |
| PUT | `/admin/drama-presets/:id/enabled` | admin | 启停 |
| PUT | `/admin/drama-presets/order` | admin | `{kind, ids:[…]}` 重排 |
| POST | `/admin/drama-presets/:id/preview` | admin | multipart 上传预览图，返回新 URL |
| DELETE | `/admin/drama-presets/:id` | super_admin | 有项目引用 → 409 并说明「只能停用」 |

写操作统一 `adminAudit(...)`，新增 target_type 常量 `drama_preset`，detail 带 `kind/key/变更字段`，
不带 prompt 全文（太长，审计表放不下也没意义）。

删除前的引用检查：`SELECT count(*) FROM drama_projects WHERE style_key = ? AND deleted_at IS NULL`，
仅 `kind=style` 走；题材引用同样查 `genre` 列。`>0` 返回 `ErrInvalidParams.WithMsg("已有 N 部短剧在用这个画风，只能停用")`。

## 6. 后台页面

新增 `web/src/pages/admin/drama-presets/`，导航挂在「模型渠道」下面（`admin-nav.ts` 加一条，label「短剧预设」，图标 `Clapperboard`）。

- 两个 Tab：题材 / 画风，各自一面卡片墙。这张墙就是开拍设置的预览：画风能直接看到效果图，题材看到的是自己的色块。
- 卡片（`preset-grid.tsx`）：16:10 媒体区 · 名称与启用开关 · key（等宽标签）· 画风描述两行 · 底部引用数与编辑。
  - 媒体区：画风是预览图（没有图就是渐变占位），题材没有图，用渐变底 + 名称首字。
  - 停用的卡：媒体区压一层底色并打「已停用」，不是只把名字变灰。
  - 拖动排序手柄压在媒体区左上角，hover / 键盘聚焦才浮出（触屏没有 hover，常显），12 张卡上不挂 12 个常驻手柄。
  - **卡片上没有删除**：预设下架一律用启用开关（§12.6）。
- 网格 `repeat(auto-fill, minmax(228px, 1fr))`，宽屏自动加列；末尾一格是虚线的「新建画风 / 新建题材」，列表非空时页面上没有工具条。
- 排序走拖拽（`PUT .../order` 一次提交整组顺序）。卡片墙是换行网格，`Reorder.Group` 必须显式 `axis="xy"`，否则只沿竖直方向算顺序。
- 新建/编辑弹窗：key 只在新建时可填（提示「小写字母、数字、下划线，创建后不可改，已有短剧靠它关联画风」）；
  画风多一个 640×400 预览图上传位与 prompt 多行框（字符计数 500）。
- 列表加载失败就地重试（后台通用规范），不弹请求错误浮层。
- 遵循 `web/docs/coding-standards.md`：清透面板（`GLASS_PANEL` + `rounded-2xl [corner-shape:squircle]`）、不写操作说明小字（原来那句「共 N 条，拖动左侧手柄可调整顺序」已删）。

## 12. 实现记录

实际落地与方案的三处偏差，都写在这里，免得后来人对着方案猜。

### 12.1 预览图不走 `URL()`，改用独立公开路由（§4.3 已同步改正）

原方案「Put 之后把 `URL()` 存进 `preview_url`」在两种存储上都行不通：本地存储给的是
`/files/<key>`（`/files` 要按 `assets` 表反查，预设没有素材行 ⇒ 404），对象存储私有桶给的是
带 ttl 的预签名地址（过期即裂图）。

落地做法：迁移 `0050_drama_preset_preview.sql` 加 `preview_key` + `preview_storage_id`，
新增公开路由 `GET /api/v1/drama-presets/previews/*`，按 key 反查预设取存储，
本地直出（复用 `storage.FileServer`，Range 与长缓存照旧）、对象存储现签名 302。
`preview_url` 存这条路由的地址，与内置条目的静态相对路径共用一个字段。

顺带处理了「手填地址」的一致性：`preview_url` 变了就把两个定位列清空，
否则预览路由还会按旧 key 返回上一张图（`TestDramaPresetUpdateClearsPreviewLocator` 钉住这条）。

### 12.2 修改接口不收 `sort_order`（§5.2 表格里的那列去掉）

排序只有一条路径：`PUT /order` 整组提交。弹窗顺手改单条 sort 会让「拖拽整组」和「单条改序」
两套机制互相打脸，而且拖拽出来的顺序本来就是整组的。单条改序没有任何运营场景需要它。

### 12.3 key 额外拦掉保留值 `custom`

`drama_projects.style_key = "custom"` 是「不用预设、手写描述」的哨兵。预设里若出现 key 为 `custom`
的画风，校验与提示词组装会撞车，所以 `Create` 直接拒绝（`TestDramaPresetKeyRules` 覆盖）。

### 12.4 其它落地细节

| 点 | 落地 |
|---|---|
| 引用计数 | 列表用一次 `GROUP BY` 拿全（`UsageCounts`），不逐条 count；删除前再单查一次，>0 返回 67039「已有 N 部短剧在用这个画风，只能停用」 |
| 校验语义 | 新建/换画风要「存在且启用」；已建项目保存其它字段只要「存在」（`checkDramaStyleKept`），停用不会锁死老项目 |
| 缓存 | 每次写操作后 `drama.InvalidateCatalog()`，单机立刻生效；多副本靠 60 秒 TTL |
| 权限 | 读与运营写 = admin / super_admin；删除 = super_admin（`superOnly`） |
| 测试 | `dramapresetfake` 提供内存 Repo / Store，服务层 12 条用例 + 接口层 8 条用例；迁移与模型一致性在本地 PostgreSQL 16 跑通 |
| 前端 | 导航「短剧预设」紧跟「模型渠道」；`pickers.tsx` 删掉 `STYLE_PREVIEW_KEYS` 白名单，改按 `previewUrl` 渲染；`admin-nav.test.ts` 钉住位置 |

### 12.5 列表改成卡片墙（§6 已同步改写）

第一版做的是列表行（和 `settings/showcase` 一样的一行一条），验收时判断为「不像配置、也不好看」：
画风的核心信息是那张效果图，行内 80px 缩略图看不出来。改成卡片墙后有三个连带决定：

1. **题材也要有媒体区。** 题材没有预览图，但两种卡片混在一面墙里时，留白高度不一致会很难看。
   题材卡用 `DramaPoster` 的稳定渐变 + 名称首字，和画风卡同尺寸，读起来像「这一类片子的色卡」。
2. **拖拽必须 `axis="xy"`。** `Reorder.Group` 默认按项目布局自动判定，换行网格会退化成只沿竖直方向算顺序，
   拖到下一行不会落到想要的位置。这个参数不写就是坏的，且不会报错。
3. **工具条整个去掉。** 原设计有一行「共 N 条，拖动左侧手柄可调整顺序」+ 新建按钮，前者违反
   `coding-standards.md` §6.2（不加操作说明小字），后者和卡片墙的风格不搭。改成末尾一格虚线「新建」卡，
   手柄压到卡片媒体区左上角、hover 才浮出；触屏没有 hover，用 `[@media(hover:none)]` 常显。

### 12.6 预设不做删除，只做停用

第一版在卡片右下角放了删除按钮（super_admin + 确认弹窗 + 被引用时禁用），验收时判断这个方向就不对：
预设是给创作端用的**目录**，`drama_projects` / `drama_scripts` 里存的是 `style_key` / `genre_key` 字符串，
没有外键。删掉一行，历史项目里那个 key 就指向不存在的东西——虽然校验做了「只认存在」的兜底、
停用不影响老项目保存，但「条目凭空消失」本身就没有运营场景需要。

所以页面上的删除入口整个去掉（卡片只剩编辑 + 启用开关），前端 `usePresetsAdmin` 的 `remove` 与
`api/admin/drama-preset` 的 `deleteDramaPreset` 一并删除，不留死代码。

后端 `DELETE /admin/drama-presets/:id` **保留**：它是 super_admin + 引用计数双重保护下的应急口子
（误建的条目、迁移脏数据），只是不再是任何界面的日常路径。真要走这条路，审计日志会记下操作人。
